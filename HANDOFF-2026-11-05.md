## What was done

1. **Review.** Ranked findings, with what's built well. Verdict: well built at its core, grown rather than designed in
   places; no rebuild needed.
2. **Data safety (review #2, #3, #7):**
   - settings.json and the standings files can't be wiped or half-written.
   - Race results can't be dropped on the way to the league site.
   - A failed series switch can't mix two series.
3. **Test suite (review #1).** Recorded races replayed through the real `IRacingSource.tick()` and `process_reading()`
   with a stand-in for iRacing, plus unit tests for race logic, live points, standings, bracket and data safety. Two
   deliberately added bugs were both caught. How to run them and add races: README, "Tests".
4. **Bug the replays found.** Talladega Oct 24, overtime caution (lap 50): 8 of 10 cars were held in their stalls
   about 2 minutes. Race off pit road gave up on them after 90 s and threw the cycle away. It now waits (up to 5 min)
   and goes READY with all 10 before the restart. Covered by `test_pit_cycle_under_the_overtime_caution`.

## Still open from the review, most important first

- **#4 `server.py` does too many jobs** (~2,800 lines). Split it into modules with no logic changes, now that the tests
  protect it: race logic, the demo races, car renders, folder and file handling, web routes.
- **#5 Work done more often than needed.** Car-render lookups (`build_grid`, `render_key`) run every reading under
  `SOURCE_LOCK`, with ~15–20 file checks per car. Each page gets its own copy of the state built under the main lock.
  Three standings iframes each poll `/state` every 300 ms. The black box holds ~30 MB in memory.
- **#6 Graphics freeze silently** if every reading fails (`telemetry_loop`): mark the data stale and say so in the panel.
- **#8 Live points match by name, then car number** (`livepoints._score`), so a renamed driver can silently take
  another's points. Flag number-only matches until plan phase 4 brings iRacing IDs.
- **#9 Per-race memory keyed by session number** (pit stops, finish gaps, flags, incident log, pit cycle): it carries
  over into a different race with the same session number. Reset on the subsession ID too.
- **#10 No login on the network.** Any device on the same network can control the overlay. `/api/browse` lists folders.
  The diagnostics zip includes the announcer producer code and link token.
- **#11 Copied code** (lap/gap text, `_status`, `_col`, name matching) and **#12 dead code and leftovers**
  (`LAST_POLL*`, `FLAG_ONE_LAP_TO_GREEN`, `PROBE_EXTRA`, `RENDER_LAST`, Standings Control leftovers, names like
  tower/lowerthird/analysis).
- **Tests:** both recordings are races. A qualifying or practice black box would cover what only the unit tests check
  now. The HTML pages have no tests.
